## Rules for every step

1. Read the newest `state/decisions/*.md` first (golden rule 1). Q3 writes the decision the
   later steps cite.
2. One issue, one branch, small commits, the issue number in every commit subject. Tick the
   issue's acceptance list in the closing comment with the command output that proves it.
3. Validation before every push: `pnpm agents:validate`, `pnpm lint`, `pnpm typecheck`,
   `pnpm test`, `pnpm build`, `pnpm docs:check`; `pnpm -C studio build` before anything that
   resolves the studio package; `pnpm -C site test:e2e` when the admin changes.
4. Never weaken budget, patch, security, evidence, stage, finance, content-quality or release
   guards (golden rule 4). Deleting a workflow step that would spend runner minutes for a
   paused venture is not weakening a guard; deleting an allowlist that remains in use is.
5. Merging does not deploy. The cron table (Q4) changes only when the owner runs
   `pnpm deploy:check` and `pnpm deploy:production`. Say so in the closing comment.
6. Money, accounts, credentials, channel enabling: `state/INBOX.md` `HUMAN_APPROVAL`, never a
   direct edit (golden rule 5).
7. Prose you write ships through `stop-slop`; owner items go to `docs/NEEDED.md` in the
   marker format.
