# Workspace fixtures

Three real days from the meeting archive, shaped the way the BoardlessAI Workspace viewer will
read them. Hand these to a designer; they are the data contract, not a mock.

- `held-meeting.json` — a room that met, wrote a decision and produced something. The delivery
  message carries the package ref in `attachment`, which is what the collapsible JSON disclosure
  opens.
- `board-day.json` — one day, three board blocks under a single date divider. The morning block
  cost money and the two checkpoints cost nothing; the viewer should be able to show that without
  making the quiet ones look broken.
- `quiet-day.json` — three rooms that did not meet, each with exactly one system line carrying its
  own recorded reason. This is the state the design most needs to get right: a room that did not
  sit is not an error, and it is not a blank.

Every one is generated by `buildMeetingFeed` in `site/src/lib/meeting-feed.ts`, so the shapes are
exactly what the implementation will receive.

Two things the design has to preserve:

- **`text` is always prose.** No refs, no hashes, no phase tokens. The only machine string in the
  model is `attachment.ref`, and it sits behind a label the reader chooses to open. A test
  (`meeting-feed.test.ts`) fails if a ref leaks into a message.
- **The model is language-neutral.** It stores the recorded text as-is. Whether the viewer renders
  Czech or English is a decision for the implementation, not for this layer.

All seven channels are always present, including the empty ones — a channel with no days is a room
that has not met yet, which the viewer should show as itself rather than hide.
