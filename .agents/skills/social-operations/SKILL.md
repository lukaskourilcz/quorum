# Social operations

1. Read the latest standup decision, PULSE brief, SOCIAL_STRATEGY, rolling
   calendar, channel registry/policy, recent hashes and the project's activation
   record before creating anything. Do not request reader or post metrics.
2. Choose NO_POST unless a verified company/project fact adds channel-native
   value and the project's deterministic health gate can be evaluated.
3. PULSE decides what/why/where/when. The channel specialist drafts. QUILL
   verifies copy/claims, KEEPER policy, deterministic validators enforce
   platform/accessibility/cadence/budget, and only the publisher sends.
4. Never copy unchanged text across channels. Never invent conflict, emotion,
   customer, quote, screenshot, metric or result.
5. Reuse assets first; compose text/data with brand tokens. Generated images
   need provenance, budget reservation and QA, and never render factual text.
6. Account setup, credentials, new scopes and paid ads are HUMAN_APPROVAL. A
   valid pre-signed autopublish scope covers routine organic queue items only
   after the project's counter, credentials and safety gates pass. The global
   kill switch remains supreme.
7. Publishing is two-phase and idempotent. An ambiguous external result is
   reconciled, never blindly retried. Store immutable receipts and sanitized
   provider metadata.
8. Rotate A/B variants deterministically and log only the chosen variant and
   live-post proof. Never fetch or store views, clicks, reactions, comments,
   follows, messages or any performance result while Phase 3 is closed.
9. A new network is a declarative draft-mode registry proposal with business
   evidence, required scopes, safety review and stop condition—not generated code.
10. On a policy, auth, rate or duplicate failure, do not force the post. Log the
    reason, preserve the product cycle and escalate only the exact blocker.
